# AFC Ticket Bot

Discord-бот для заявок игрового сообщества Foxhole. Работает на `discord.py`,
PostgreSQL и Docker Compose.

Добавлены FastAPI backend и PySide6 CRM: постоянная панель заказов Discord,
Kanban, история, права, WebSocket и общий калькулятор. Инструкция подключения,
выпуска токенов, тестирования и текущие ограничения: [docs/CRM.md](docs/CRM.md).

Бот состоит из независимых модулей Foxhole Orders, Foxhole Calculator,
Self Roles и Recruitment. Общие permissions, audit log и реестр persistent views
используются всеми модулями.

## Панели самовыдачи ролей

В `/afc-admin` → **Панели самовыдачи ролей** администратор может
создать несколько постоянных панелей, настроить канал, текст,
emoji, порядок и Discord-роли. Кнопка выдаёт роль или снимает её при
повторном нажатии. Роли с опасными permissions или роли выше роли бота
добавить нельзя.

## Вступление в клан

В `/afc-admin` → **Вступление в клан** настраиваются постоянная панель,
вопросы многошаговой формы, категория приватных тикетов, роли
рекрутеров, роль после принятия и шаблон имени канала. Заявка может
иметь статус `PENDING`, `ACCEPTED` или `REJECTED`; закрытие блокирует
канал, но не удаляет его историю.

## Заказы Foxhole

Бот умеет распознавать русские названия, алиасы, склонения, опечатки и калибры:

```text
15 ящиков аргенти
15 ящиков 762
5 бердышей
```

Перед созданием канала пользователь получает закрытый предпросмотр. Обычные
предметы считаются в ящиках, техника — поштучно. В карточке показывается обычная
цена и максимальная MPF-партия. После подтверждения исходная фраза остаётся в БД
только для аудита, а в главном сообщении тикета её заменяет нормализованный заказ:

```text
Фальшион — 15 шт.
(135 RMat или 6 ящиков + 15 RMat в гараже за шт. /
1 619 RMat или 80 ящиков + 19 RMat на MPF за 5 ящиков техники)
```

Структурированные позиции и ценовые snapshots используются повторно при каждом
обновлении главного сообщения, поэтому последующая синхронизация каталога не
меняет цены уже созданного заказа.

### Настройка формы

1. Откройте `/afc-admin` → **Формы**.
2. Создайте или выберите форму.
3. Добавьте многострочное поле с типом `foxhole_order`.
4. Привяжите форму к нужной панели тикетов.

Остальные типы полей (`text`, `long_text`) продолжают работать без изменений.

## Каталог и алиасы

В `/afc-admin` доступен раздел **Каталог Foxhole**. В нём можно обновлять
технические данные, искать предметы, менять русское название, добавлять и удалять
жаргонизмы. Доступ имеют только администраторы Discord и настроенная роль
администратора бота.

Быстрые административные команды:

```text
/afc-items-refresh
/afc-foxhole-status
/afc-foxhole-untranslated
/afc-item-search
/afc-item-alias-add
/afc-item-alias-remove
/afc-item-rename
/afc-item-override
/afc-item-debug
/afc-unknown-aliases
/afc-dictionary-export
/afc-dictionary-import
```

`/afc-item-override` вручную исправляет категорию, цену, производственное здание,
размер обычного и транспортного ящика, признак техники и параметры MPF. Ручные
значения имеют приоритет над FoxholeHQ.

## Foxhole-калькулятор

`/calc` рассчитывает запрошенное количество отдельно для каждого доступного
способа производства: Factory/Garage, MPF и Facility. Обычные перевозимые в
ящиках предметы принимаются в ящиках; техника, контейнеры, Facility-материалы и
крупные переносимые предметы — в штуках. Для MPF бот разбивает заказ на
допустимые очереди, показывает расчёт заказа и справочную стоимость минимальной
и максимальной очереди (3/9 ящиков либо 3/5 для техники).

`/train` собирает состав до 15 локомотивов и вагонов и суммирует Facility-ресурсы.
Администратор управляет cache, алиасами и ручными рецептами через `/calc-admin`
или раздел **Foxhole Calculator** в `/afc-admin`; `/calc-debug` показывает
исходные ID, единицы, рецепты, версии и источник данных.

## Источник данных

Основной источник игровых данных — актуальный [Foxhole Queues Calculator](https://foxholehq.net/factory)
FoxholeHQ. У сайта нет публичного API каталога: сведения о предметах, очередях,
ценах и фракциях находятся в структурированных атрибутах серверной страницы
`/factory`, а названия и размеры ящиков — в tooltip-разметке. Бот разбирает HTML
без выполнения стороннего JavaScript.

```env
FOXHOLEHQ_BASE_URL=https://foxholehq.net
FOXHOLEHQ_SYNC_INTERVAL_HOURS=24
FOXHOLEHQ_MIN_ITEMS=100
FOXHOLE_RESOURCE_COST_DISPLAY=both
FOXHOLE_WIKI_ENABLED=true
FOXHOLE_WIKI_API_URL=https://foxhole.wiki.gg/api.php
```

Синхронизация скачивает dataset, проверяет заявленную версию и
минимальное число предметов/рецептов/техники/оружия и только после этого обновляет
PostgreSQL. Хранятся версия, SHA-256, время успешной синхронизации и последняя
ошибка. Повторный dataset с тем же хэшем не переписывает каталог.

Facility и железнодорожные рецепты дополняются текущими структурированными
infobox-полями Foxhole Wiki. FoxholeHQ остаётся приоритетным источником, поэтому
совпадающий рецепт из Wiki его не заменяет.

Тикеты и пользовательские расчёты всегда читают локальный PostgreSQL и не
обращаются к upstream-сайтам. Если сайт
недоступен или изменил bundle, бот продолжает работать на последнем успешном
FoxholeHQ dataset; старый `foxhole-item-api` не используется. До первого успешного
импорта вымышленные или архивные цены не подставляются.

Русские названия, алиасы и ручные параметры хранятся отдельно. Новые предметы
получают статус `missing`, исчезнувшие деактивируются без удаления. В позиции
заказа сохраняется snapshot названия, Factory/Garage/MPF цен, размера ящика,
версии dataset и времени синхронизации.

Подробности фактического upstream-контракта: [docs/FOXHOLEHQ.md](docs/FOXHOLEHQ.md).

## Переменные окружения

Скопируйте `.env.example` в `.env` и задайте обязательные значения:

```env
DISCORD_TOKEN=...
POSTGRES_PASSWORD=...
```

`DISCORD_GUILD_ID` используется для немедленной синхронизации основного сервера,
но не ограничивает бота одним сервером. Глобальные команды публикуются для всех
серверов, а при подключении к новому серверу бот сразу создаёт guild-копию команд.

Пороги распознавания и названия ресурсов также задаются через `.env.example`.

## Запуск

```bash
docker compose up -d --build
docker compose logs -f bot
```

При старте бот автоматически выполняет `alembic upgrade head`. Существующая БД
не пересоздаётся, данные тикетов сохраняются.

## Тесты

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

Подробные команды установки, обновления и резервного копирования VPS находятся
в [DEPLOY.md](DEPLOY.md).
