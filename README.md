# AFC Ticket Bot

Discord-бот для заявок игрового сообщества Foxhole. Работает на `discord.py`,
PostgreSQL и Docker Compose.

## Заказы Foxhole

Бот умеет распознавать русские названия, алиасы, склонения, опечатки и калибры:

```text
15 ящиков аргенти
15 ящиков 762
5 бердышей
```

Перед созданием канала пользователь получает закрытый предпросмотр. Обычные
предметы считаются в ящиках, техника — поштучно. В карточке показывается обычная
цена и максимальная MPF-партия.

### Настройка формы

1. Откройте `/afc-admin` → **Формы**.
2. Создайте или выберите форму.
3. Добавьте многострочное поле с типом `foxhole_order`.
4. Привяжите форму к нужной панели тикетов.

Остальные типы полей (`text`, `long_text`) продолжают работать без изменений.

## Каталог и алиасы

В `/afc-admin` доступен раздел **Каталог Foxhole**. В нём можно обновлять
технические данные, искать предметы, менять русское название, добавлять и удалять
жаргонизмы. Доступ имеют только администраторы Discord и настроенная роль
администратора бота.

Быстрые административные команды:

```text
/afc-items-refresh
/afc-foxhole-status
/afc-foxhole-untranslated
/afc-item-search
/afc-item-alias-add
/afc-item-alias-remove
/afc-item-rename
/afc-item-override
```

`/afc-item-override` вручную исправляет категорию, цену, производственное здание,
размер обычного и транспортного ящика, признак техники и параметры MPF. Ручные
значения имеют приоритет над FoxholeHQ.

## Источник данных

Основной источник игровых данных — актуальный [Foxhole Queues Calculator](https://foxholehq.net/factory)
FoxholeHQ. У сайта нет публичного API каталога: сведения о предметах, очередях,
ценах и фракциях находятся в структурированных атрибутах серверной страницы
`/factory`, а названия и размеры ящиков — в tooltip-разметке. Бот разбирает HTML
без выполнения стороннего JavaScript.

```env
FOXHOLEHQ_BASE_URL=https://foxholehq.net
FOXHOLEHQ_SYNC_INTERVAL_HOURS=24
FOXHOLEHQ_MIN_ITEMS=100
```

Синхронизация скачивает dataset, проверяет заявленную версию и
минимальное число предметов/рецептов/техники/оружия и только после этого обновляет
PostgreSQL. Хранятся версия, SHA-256, время успешной синхронизации и последняя
ошибка. Повторный dataset с тем же хэшем не переписывает каталог.

Тикеты всегда читают локальный PostgreSQL и не обращаются к FoxholeHQ. Если сайт
недоступен или изменил bundle, бот продолжает работать на последнем успешном
FoxholeHQ dataset; старый `foxhole-item-api` не используется. До первого успешного
импорта вымышленные или архивные цены не подставляются.

Русские названия, алиасы и ручные параметры хранятся отдельно. Новые предметы
получают статус `missing`, исчезнувшие деактивируются без удаления. В позиции
заказа сохраняется snapshot названия, Factory/Garage/MPF цен, размера ящика,
версии dataset и времени синхронизации.

Подробности фактического upstream-контракта: [docs/FOXHOLEHQ.md](docs/FOXHOLEHQ.md).

## Переменные окружения

Скопируйте `.env.example` в `.env` и задайте обязательные значения:

```env
DISCORD_TOKEN=...
POSTGRES_PASSWORD=...
```

Пороги распознавания и названия ресурсов также задаются через `.env.example`.

## Запуск

```bash
docker compose up -d --build
docker compose logs -f bot
```

При старте бот автоматически выполняет `alembic upgrade head`. Существующая БД
не пересоздаётся, данные тикетов сохраняются.

## Тесты

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

Подробные команды установки, обновления и резервного копирования VPS находятся
в [DEPLOY.md](DEPLOY.md).
